# 在庫管理（Web 版）

本アプリを実行するPC(以降「サーバーPC」）以外に、と同じローカルネットワークの PC・スマホのブラウザからも入出庫可能な在庫管理システムです。

ポート番号を任意に設定します。（既定は 28003。変え方は「ポートや保存先を変える」）。

- **PC用画面**（`http://サーバーPC:28003/`）：商品の登録・編集・削除（画像・保管場所付き）、一覧・検索、入庫・移管・出庫、在庫警告、履歴、設定
- **スマホ用画面**（`http://サーバーPC:28003/m`）：ID入力 または QR読み取り → 場所・現在在庫を表示 → **入庫・移管・出庫**
- 移管 = 人・部署への払い出し（在庫は減り、移管先を履歴に記録。過去の移管先は候補に表示）
- 在庫不足の出庫・移管は拒否
- 在庫警告（警告在庫以下の商品）、入出庫履歴、CSV 出力
- QR コード・バーコード（JAN / EAN / CODE128 など）の読み取り
- 入力者は名前を選ぶ方式。**操作した端末の IP アドレス**も履歴・操作ログに記録
- ローカルネットワーク（プライベートアドレス）以外からの接続は拒否

## 1. サーバーPCへの導入

### 必要なもの
- Windows 10 / 11
- **Node.js 24 LTS**（22.13 以上）… https://nodejs.org/ja/download からインストーラーで導入

### 手順
1. この ZIP をサーバーPCの任意の場所（例: `C:\zaiko-web`）に展開
2. `start.bat` をダブルクリック
3. 表示されたアドレス（例: `http://192.168.1.20:28003`）をブラウザで開く
4. 「設定」画面で入力者（使う人の名前）を登録
5. スマホは同じローカルネットワーク（Wi-Fi）に接続し、「設定」画面の QR コードを読み取ってスマホ用画面（`/m`）を開く
   （ホーム画面に追加すると、アプリのように起動できます）

> 初回起動時に Windows のファイアウォール確認が出たら「プライベートネットワーク」のみ許可してください。

### PC 起動時に自動で起動する（推奨）
`register-autostart.bat` を **右クリック →「管理者として実行」**。以下を行います。
- PC 起動時（ログオン前）にサーバーを起動するタスクを登録（タスク名 `ZaikoWeb`）
- ファイアウォールで、**同じサブネット（社内LAN）からの** 設定したポート（既定 28003）への接続だけを許可

自動起動中のログは `data\server.log` に出ます。解除は `unregister-autostart.bat`（管理者として実行）。

### ポートや保存先を変える
**ポートの既定値は 28003** です。変えるときは `settings.bat` を編集します。

```bat
set ZAIKO_PORT=28003
rem set ZAIKO_DATA_DIR=D:\zaiko-data
```

- `settings.bat` は初回起動時に `settings.example.bat` から自動で作られます（無ければ 28003 で動きます）。
- `settings.bat` は GitHub で管理しないファイルです。`update.bat` で更新しても消えず、更新が止まることもありません。
  （`start.bat` などを直接書き換えると、`update.bat` は「書き換えあり」として更新を中止します）
- `start.bat` / `run-server.bat` / `register-autostart.bat` は、`load-settings.bat` を通して `settings.bat` を読みます。

ポート変更後にすること：
1. `register-autostart.bat` を管理者として実行（ファイアウォールの許可を新しいポートに切り替え、サーバーを再起動）。自動起動を使っていない場合は `start.bat` を起動し直す
2. QR ラベルにはポート入りのアドレスが入っているので、**印刷し直す**。スマホのブックマーク、メール設定の「画面のアドレス」（手入力している場合）も直す

## 2. データとバックアップ

`data` フォルダにすべて保存されます。

| パス | 内容 |
|---|---|
| `data\zaiko.db` | データベース（SQLite） |
| `data\images\` | 商品画像 |
| `data\backup\` | DB の自動バックアップ（1日1回。残す期間は設定画面で選択、既定 毎日の分を30日） |
| `data\logs\` | 履歴の CSV 控え（月別：入出庫履歴・操作ログ・ID変更履歴。1時間ごと・終了時に更新） |

### 自動バックアップの設定（設定画面 →「バックアップ」）
- **毎日の分を残す期間**：7日 / 30日（既定）/ 90日 / 1年 / 無制限
- **月1回の分も残す**（任意。既定はオフ）：毎月の指定日（1〜28日・月末）の分を、12か月 / 24か月 / 36か月 / 無制限 残します。
  - 例：毎日の分 30日 ＋ 月末の分を無制限 → 直近1か月は毎日、それより前は各月末の状態に戻せます。
  - 指定日の分が無い月（サーバーPCが止まっていた等）は、それ以降で最初の分を残します（月末が休みなら翌月1日の分）。
- **無制限**は古いバックアップを消しません。保存先の空き容量が少しずつ減るので、画面の「合計」「空き」を時々確認してください（空きが 1GB を切ると画面の上に警告が出ます）。
- **追加の保存先**（任意）：外付けドライブ・USB メモリのフォルダ（例: `E:\zaiko-backup`）。PC の故障に備えて指定をおすすめします。
  - `db\` にデータベース、`images\` に商品写真をコピーします（写真は増えた・変わった分だけ。削除した商品の写真も消さずに残します）。
  - 抜いていた日の分は、挿し直すと次の確認（1時間ごと）でまとめてコピーします。保存できていない間は、PC 用画面の上に警告が出ます。
  - ドライブ文字が変わると保存できません。Windows の「ディスクの管理」→ ドライブを右クリック →「ドライブ文字とパスの変更」で、後ろの方の文字（例: Z:）に固定しておくと確実です。
  - **NAS などネットワークの場所は指定できません**（サーバーは Windows の SYSTEM として動くため、NAS に認証できません）。
  - 指定したら「書き込みテスト」で確認してください（会社の設定で USB 記憶装置への書き込みが禁止されている場合は、ここで分かります）。

### 元に戻す（復元）
1. サーバーを止める（自動起動の場合はタスクスケジューラーで `ZaikoWeb` を終了、`start.bat` の場合はその画面を閉じる）
2. `data\zaiko.db` を別名に変えて退避し、`zaiko.db-wal` / `zaiko.db-shm` があれば一緒に退避する
3. 戻したい日のバックアップ（`zaiko_YYYYMMDD.db`）を `data\zaiko.db` という名前でコピーする
4. 写真が無くなっている場合は、追加の保存先の `images\` の中身を `data\images\` にコピーする（同じ名前のファイルは上書きしない）
5. サーバーを起動する
- `zaiko.db-wal` / `zaiko.db-shm` は稼働中の DB の一部です。サーバー稼働中に `zaiko.db` だけをコピーしないでください（`backup` フォルダのファイルは単体で完全なコピーです）。

## 3. 更新（新しいバージョンに入れ替える）

1. サーバーを止める（`start.bat` の画面で Ctrl+C、自動起動の場合はタスクスケジューラで `ZaikoWeb` を終了）
2. `data` フォルダ**以外**を新しいものに置き換える
3. 起動する（DB の構造変更が必要な場合は起動時に自動で行われます）

## 4. 使い方のポイント

- **入力者**：各端末で最初に名前を選びます（画面右上で変更可）。選んだ名前は端末ごとに記憶されます。
- **端末の IP と入力者の紐づけ**：「設定」→「入力者」で端末の IP アドレスを人に紐づけると、その端末では名前を選ばなくてもその人として記録します（画面で名前を選んだ場合はそちらが優先）。
  名前なしで記録された端末の IP は同じ画面に一覧で出るので、そこから紐づけられます（過去の履歴は書き換えません）。
  サーバーPC本体（127.0.0.1）は複数人が使うため紐づけできません。IP が変わると紐づけが外れるため、ルーターで端末ごとに IP を固定（DHCP 予約）するのが確実です。
- **紐づけID（受注番号等）**：入庫・出庫・移管で任意入力。`data\link-ids.txt`（1行1件。以前の名前 `受注番号リスト.txt` も、`link-ids.txt` が無ければ読みます。案件フォルダ名そのまま「受注番号_案件名」、または番号だけ）から候補を出し、番号・案件名（ひらがな可）で絞り込めます。リストに無い番号も入力でき、最近の手入力も候補に出ます。
  リストの番号は表記ゆれ（全角・小文字・ハイフンなし）をリストの表記にそろえて記録します。ファイルを置き換えると自動で反映（UTF-8 / Shift_JIS / UTF-16 どれでも可）。履歴 CSV に「紐づけID」列があります。
  入力した紐づけIDは、商品を切り替えても残ります（同じ受注の部品を続けて出庫するため）。不要なら × で消してください。
- **履歴ページ**（PC、上のメニューの「履歴」）：入出庫・履歴の修正・操作ログ・ID変更を表示。期間は既定で直近3か月、「半年」「1年」「全期間」「年度」のボタンで開始日・終了日に入り、日付を直接変えれば任意の期間。
  年度の隣の「○月決算」で決算月（既定 3月＝4月始まり）を選びます。選んだ月はサーバーPCに保存され、次回も・他の端末でも同じです（変更は操作ログに残ります）。年度は始まった年で呼びます（例: 9月決算なら 2026年度 = 2026/10〜2027/9）。
  キーワード（ひらがな・カタカナ・ハイフンの違いを無視）、区分、入力者、取消の扱い、紐づけIDで絞り込み、入出庫の合計（取消分を除く）を表示。「この条件でCSV出力」で同じ条件の全件を CSV に。商品パネルの「すべての履歴を見る」からはその商品だけを表示。
- **履歴の修正・取消**（PC）：履歴の行をクリックすると詳細が開きます。直せるのは**紐づけIDとコメント**です。数量・区分の間違いは「取消」（理由必須）で逆向きの「取消」履歴を作って在庫を戻し、入力し直します（元の履歴は消えず「取消済」になります）。
  直した内容・取消はすべて「修正履歴」（日時・修正前・修正後・入力者・IP）に残り、`data\logs\履歴の修正_YYYY-MM.csv` にも保存されます。初期登録・棚卸調整は取り消せません（在庫調整で直す）。
- **端末と入力者の紐づけ**：各端末（ブラウザ）には初回アクセス時に Cookie で端末IDが付き、「設定」→「端末」に一覧で載ります。端末を人に紐づけると、その端末では名前を選ばなくてもその人として記録します（IP が変わるスマホ向け。端末の紐づけ → IP の紐づけ の順に使います）。
  ブラウザの Cookie を消す・別のブラウザ・プライベートブラウズでは別の端末になります。
- **写真の拡大**：詳細欄・スマホの商品表示・編集画面の写真をクリック（タップ）すると大きく表示します。Esc・背景のクリックで閉じます。
- **入出庫**：一覧で商品を選ぶ（スマホでは下からパネルが出ます）→ 数量 →「入庫」/「出庫」
- **読み取り**：「読み取り」ボタン → 登録済みなら商品を選択、未登録なら新規登録画面をコード入力済みで開きます。
  USB バーコードリーダー（キーボード入力型）は、検索欄で読み取ると商品を選択します。
- **在庫数の修正**：編集画面では在庫数を変えられません（必ず履歴を残すため）。入庫・出庫で調整してください。
- **同時編集**：同じ商品を2人が同時に編集した場合、後から保存した人に「他の人が更新しました」と表示されます。
- **他の端末の操作**は 10 秒ごとに画面へ反映されます。

- **簿外**：商品編集画面のチェックで設定。一覧の「簿外」プルダウンで絞り込めます。在庫警告・警告メールの対象には含めます（メールでは「（簿外）」と表示）。在庫CSVの「簿外」列は ○ か空欄。
- **商品IDの変更**：保存時に確認が出て、旧→新ID・入力者・IP を記録します。詳細欄に旧IDを表示し、旧IDのラベルを読み取っても現在の商品が開きます。
- **履歴のCSV控え**：`data\logs` に月別の CSV を自動保存します（設定画面に保存先と前回の結果、「今すぐ書き出す」ボタン）。今月・先月は毎回作り直し、それより前の月は手を加えません。Excel で開いたままだと更新できないため、閉じれば次回（1時間以内）に更新されます。
- **購入元**：商品編集画面で5件まで（名前＋URL）登録できます。PC の詳細欄・スマホの商品表示にリンクで出ます。

### メール通知（在庫警告）
「設定」→「メール通知」で、メールサーバー（SMTP）・送信元・宛先・送信時刻を設定します。
- 警告在庫以下の商品があるときだけ、1日1回、一覧（在庫・場所・購入元・スマホ画面へのリンク）を送ります。
- 送信時刻にPCが止まっていた場合は、起動後にその日の分を送ります。失敗したら30分おきに3回まで再試行します。
- 「テスト送信」は保存前の入力内容で送ります。結果（成功・失敗の原因）は画面下に残ります。
- 一般的な組み合わせ：社内リレー＝25番・暗号化なし / 認証付き送信＝587番・STARTTLS / 465番・SSL。
- SMTP のパスワードは `data\zaiko.db` に**暗号化せず**保存されます（画面には返しません）。`data` フォルダのアクセス権に注意してください。
  サーバーPCの外向き 25 番ポートが塞がれている環境では送れません（その場合はメールサーバーの管理者に、送信可能なサーバー・ポートを確認してください）。

### スマホのカメラでの読み取りについて
ブラウザの制約で、`http://` の画面ではカメラ映像からの連続読み取りが使えません。
そのためスマホでは「撮影して読み取る」方式（写真を1枚撮ると自動で読み取り）になります。

## 5. 開発

開発を引き継ぐ人・AI へ：作業ルールは [AGENTS.md](AGENTS.md)、経緯・設計判断・残課題は [docs/HANDOVER.md](docs/HANDOVER.md) にまとめています。

```bash
npm install
npm run dev        # 開発用サーバー（画面 http://localhost:5173 、API は 28003）。データは dev-data/
npm test           # サーバーの単体テスト・API テスト（vitest）
npm run build      # 型チェック + 画面のビルド + サーバーを dist/server.mjs に1ファイル化
npm run e2e        # ブラウザでの動作確認（要: npx playwright install chromium）。画面写真は e2e/shots/
```

### 構成

```
shared/            サーバーと画面で共有する型・定数・検索ルール
server/src/
  main.ts          起動・自動バックアップ
  backup.ts        自動バックアップ（残す期間・追加の保存先・写真のコピー）
  updater.ts       画面からのプログラム更新（サーバーPCの画面のみ）
  app.ts           HTTP（API・画面ファイル配信・ローカルネットワーク判定・セキュリティヘッダー）
  inventory.ts     業務ルール（登録・更新・削除・入出庫・入力者）
  db.ts            SQLite（Node.js 内蔵）・DB 構造の更新（PRAGMA user_version）
  images.ts        画像の受け取り・保存
  network.ts       社内（プライベート）アドレス判定
  csv.ts           CSV 出力
server/test/       単体テスト・API テスト（一時フォルダに本物の DB を作って検証）
web/src/           画面（React + TypeScript）
e2e/               ブラウザでの動作確認スクリプト
```

### 設計メモ（主な判断とトレードオフ）

| 判断 | 理由 | デメリット・注意 |
|---|---|---|
| Node.js 内蔵の SQLite（`node:sqlite`） | ネイティブモジュールのビルドが不要で、サーバーPCは Node.js を入れるだけで動く | Node.js 側では「実験的機能」扱い（警告は非表示にしている）。Node.js の大きな更新時は動作確認が必要 |
| サーバーを1ファイルにまとめる（esbuild） | サーバーPCに `npm install` 不要。更新はファイルの置き換えのみ | — |
| 在庫の増減は `UPDATE ... WHERE 増減後の在庫が範囲内` | 複数端末から同時に出庫しても在庫がマイナスにならない | — |
| 商品の編集は version による楽観的排他制御 | 同時編集で他人の変更を黙って上書きしない | 後から保存した人は開き直しが必要 |
| 画像の縮小・回転補正はブラウザ側 | サーバーに画像処理ライブラリが不要。スマホからの送信量も小さい | サーバー側は形式（先頭バイト）とサイズのみ検証 |
| 入力者は名前の選択のみ（パスワードなし） | 共有スマホでも手間がかからない | 本人確認ではない（他人の名前も選べる）。抑止として端末 IP を記録 |
| 社内アドレス以外は 403 | ルーター設定ミス等で外部に公開されても使われないようにする二重の防御 | VPN 経由などで社外のアドレスから使う場合は `server/src/network.ts` の許可範囲を変更 |
| 更新系は JSON / 画像のみ受け付け | 他サイトからのフォーム送信による不正操作（CSRF）を防ぐ | — |

### 制限事項・今後の候補
- 端末の IP は DHCP で変わることがあるため、厳密な端末特定が必要なら IP 固定（DHCP 予約）を推奨
- 商品数が数万件を超える場合は検索方式（全文検索）の見直しが必要
- 棚卸し（実在庫との差異調整）、ロケーション（保管場所）管理、ログイン認証は未実装

## GitHub から更新する（サーバーPC）

ソースは GitHub（Private リポジトリ）で管理しています。サーバーPCでは `update.bat` で最新に更新できます。

### 初回の準備（1回だけ）
1. サーバーPCに「Git for Windows」を入れる（https://git-scm.com/download/win 。設定は既定のままで可）。
2. `setup-github.bat` を今の在庫管理のフォルダ（`data` フォルダがある場所）に置いてダブルクリック
   （自動起動を登録している場合は右クリック →「管理者として実行」）。GitHub とつないで、そのまま更新・ビルド・再起動まで行います。
   手で行う場合は、同じフォルダで PowerShell を開き、次を実行する
   （`data` は Git の管理外なので、在庫データ・写真・設定は消えません）。
   ```powershell
   git init -b main
   git remote add origin https://github.com/hilosol/ZaikoOnWeb.git
   git fetch origin
   git reset --hard origin/main
   git branch --set-upstream-to=origin/main main
   ```
   初回の `git fetch` で GitHub へのサインイン画面が出るので、リポジトリを見られるアカウントでサインインします。
   サーバーPCに個人のアカウントを残したくない場合は、このリポジトリの「読み取り専用」に限った Fine-grained token を作って使ってください。

### 更新するとき
- `update.bat` をダブルクリック（自動起動を登録している場合は右クリック →「管理者として実行」）。
- 最新を取得 → 必要なパッケージを入れる → ビルド → サーバーを再起動、まで自動で行います（1〜数分）。
- 更新が無ければ何もしません。ビルドし直したいときは `update.bat --force`。
- このPCでプログラムのファイル（bat ファイル等）を書き換えていると、混ざらないよう中止します。
- ビルドに失敗した場合は、前の版に戻してサーバーを起動し直します（使い続けられます）。
- 自動起動を登録していない場合は、`start.bat` の画面を閉じてから実行し、終わったら `start.bat` で起動してください。

### 画面から更新する（サーバーPCの画面のみ）
サーバーPCのブラウザで在庫管理を開くと、新しい版があるとき画面の上に「新しい版があります」と出ます（6時間ごとに確認）。
「内容を見て更新」→ 変更内容を確認 →「更新する」で、`update.bat` と同じ処理（取得 → ビルド → 再起動）を行います。
他のPC・スマホにはお知らせもボタンも表示されず、操作もできません（サーバーが接続元を確認します）。

準備（1回だけ）：
1. `register-autostart.bat` を右クリック →「管理者として実行」（更新用のタスク `ZaikoWebUpdate` を登録します。既に登録済みでも、もう一度実行）
2. `update.bat` を一度実行（GitHub への接続の設定を、このフォルダに引き継ぎます）
3. GitHub で **Fine-grained token** を作る：対象リポジトリは `hilosol/ZaikoOnWeb` のみ、権限は **Contents: Read-only**、期限付き
4. サーバーPCの画面で「設定」→「プログラムの更新」にトークンを貼り付けて保存

- 画面からの更新はサーバー（Windows の SYSTEM）として動くため、利用者の GitHub サインインは使えず、トークンが必要です。トークンは `data\github-credentials` に保存されます（画面には表示しません）。期限が切れたら作り直して保存し直してください。
- 経過は `data\update.log`、結果は設定画面の「最後の更新」に出ます。失敗しても前の版で動き続けます。
- 更新中は数分間、すべての端末で使えなくなります。入力中の人がいないときに行ってください。
