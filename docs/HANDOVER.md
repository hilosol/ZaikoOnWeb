# 引き継ぎメモ（ZaikoOnWeb）

AI・人のどちらが引き継いでも、ここを読めば「なぜ今こうなっているか」と「何が残っているか」が分かるようにするためのメモです。
作業ルールは `AGENTS.md`、使い方は `README.md` を参照してください。
（2026-11-07 時点。Claude との会話で開発。以降の変更はこのファイルにも追記してください）

---

## 1. 経緯

- 元は WPF/.NET の在庫管理アプリ（ZaikoPOS）。社内の誰もが PC・スマホのブラウザから使えるよう、Web 版として作り直した
- サーバーPC（Windows、IP は 192.168.0.210 想定、ポート 28003）で Node.js サーバーを動かす。アプリのフォルダはサーバーPCのローカル HDD 上
- 開発は Claude（チャット）で行い、毎回 GitHub（`hilosol/ZaikoOnWeb`、Private）に push している

## 2. 主な機能

| 機能 | 場所 | 補足 |
|---|---|---|
| 在庫一覧・検索・入庫・移管・出庫 | PC 画面 `pages/InventoryPage.tsx`、スマホ `mobile/MobileApp.tsx` | 検索は表記ゆれを吸収（`shared/text.ts` の searchKey：全角半角・ハイフン・カタカナ/ひらがな） |
| 商品登録・編集（写真・購入元・簿外） | `pages/ProductEditPage.tsx` | 写真は送る前に長辺 1024px・JPEG 85% に縮小 |
| QR ラベル・カメラでの読み取り | `components/QrLabelDialog.tsx`, `components/Scanner.tsx` | 旧ID のラベルを読んでも現在の商品を開く |
| 紐づけID（受注番号等） | `components/OrderNoField.tsx` | `data\link-ids.txt`（1行1件）の候補から選ぶか手入力。旧名 `受注番号リスト.txt` も読む |
| 履歴ページ（入出庫・履歴の修正・操作ログ・ID変更） | `history/` | 既定は直近3か月。半年・1年・年度ボタン、決算月は年度の隣で選ぶ（全端末で共通） |
| 履歴の修正・取消 | `HistoryDialog.tsx` | 直せるのはコメントと紐づけIDだけ。修正は history_edits、取消は逆向きの CANCEL 履歴 |
| 入力者と端末の紐づけ | 設定 →「端末」 | 端末ID（Cookie `zaiko_device`、5年）で人に紐づける。名前の決まり方：選んだ名前 → 端末 → IP → 空 |
| 在庫警告メール | 設定 →「メール通知」, `server/src/mail/` | SMTP 設定は画面から |
| 履歴CSVの自動保存 | 設定 →「履歴のCSV保存」, `logExport.ts` | 月別ファイル（BOM付き）。ファイル名は日本語のまま（下の残課題） |
| 自動バックアップ | 設定 →「バックアップ」, `backup.ts` | 毎日の分＋月1回の分（任意）。外付けドライブ・USB への追加保存（DB と写真） |
| 同時編集の対策 | `presence.ts`, `pages/productMerge.ts` | 「編集中」の表示＋保存がぶつかったら項目ごとに合わせる |
| 画面からのプログラム更新 | `updater.ts`, `web/src/update.tsx` | サーバーPCの画面だけ。6時間ごとに確認し、あれば上部にお知らせ |
| デモ環境 | `start-demo.bat`（ポート 28004）, `scripts/seed-demo.ts` | 本番に近い量の架空データ |

## 3. 設計判断と理由（変える前に読む）

| 判断 | 理由 | 検討して採らなかった案 |
|---|---|---|
| DB は node:sqlite（ファイル1つ） | サーバーPCに DB サーバーを入れずに済む。バックアップはファイルのコピー | MySQL 等（運用の手間） |
| サーバーは 1 ファイル（dist/server.mjs）にビルド | サーバーPCでの配置・更新を単純に | — |
| 端末の識別は Cookie の端末ID | スマホは IP が変わる。MAC アドレスはブラウザから取れず、同じLANでも ARP は IP 変更・ルーター越しで当てにならず、スマホは「プライベート Wi-Fi アドレス」で MAC も変わる | MAC アドレス、IP のみ |
| 履歴で直せるのはコメント・紐づけIDだけ | 数量・商品は在庫の整合に関わる。間違いは取消して入力し直す | 何でも直せる編集 |
| 在庫数は入出庫でしか変えない | 必ず履歴が残るように。入出庫はサーバーで差分計算するので同時操作でも正しい | 編集画面で在庫数を直接変える |
| 同時編集は「編集中の表示」＋「項目ごとに合わせる」 | ロックは開いたまま帰ると誰も編集できなくなる。編集中は15秒ごとの知らせ（ポーリング）で、90秒途絶えたら消える | 編集ロック、SSE/WebSocket（スマホのスリープで切れる） |
| 画面からの更新はサーバーPCの画面だけ | 依頼者の方針：利用者に「アプリがインターネットにつながっている」と思わせたくない。接続元がサーバーPC自身のアドレスかで判定 | どの端末からでも押せるボタン、パスワード |
| 更新は別タスク（ZaikoWebUpdate）で実行 | サーバー自身を止めて再起動するため、サーバーの子プロセスでは途中で止まる | サーバーから直接 update.mjs を起動 |
| 画面からの更新には読み取り専用トークン | 自動起動のサーバーは SYSTEM で動き、利用者の GitHub サインイン情報を使えない。トークンは `data\github-credentials`、このフォルダの git 設定（credential.helper）からだけ使う | 利用者のサインインの流用（不可）、Deploy key（SSH のポートが塞がれている可能性） |
| バックアップの追加保存先は外付けドライブ・USB だけ | NAS は SYSTEM から認証できない（ドライブ文字は利用者ごと、ドメイン無しならゲスト扱い）。依頼者が NAS は却下 | NAS（資格情報を保存する／タスクを特定ユーザーで動かす） |
| 写真のバックアップは圧縮せず差分コピー | 写真は登録時に圧縮済みで zip にしてもほぼ縮まない。1枚ずつ戻せる。削除した商品の写真も残す | 毎回 zip |
| ポートは settings.bat 1か所 | bat を直接書き換えると update.bat が「書き換えあり」で止まる | 各 bat に直書き、data\config.json |
| data のファイル名は英語 | zip の展開で日本語名が文字化けした（`受注番号リスト.txt`） | — |
| bat は ASCII・CRLF、Python 等でバイト列として書く | 日本語の bat はサーバーPCで文字化け。シェル経由だと `>nul` が書き換わったことがある | — |

## 4. サーバーPCの状況（分かっている範囲）

- Node.js v24.19.0、Git for Windows を導入済み
- GitHub への接続は、最初 HTTPS の証明書エラー（`SEC_E_UNTRUSTED_ROOT`）で失敗 → その後 fetch できるようになった（原因と対処の詳細は未確認。`http.sslBackend openssl` を設定した可能性が高い）
- `setup-github.bat` が途中で失敗し、`.git` が中途半端な状態で残った → `rmdir /s /q .git` してやり直すよう案内済み（結果は未確認）
- スマホからの接続：サーバーPCで 28003 のファイアウォール許可が必要だった（登録済み）
- 依頼者の自宅PC（会社管理）はネットワークが「パブリック」でグループポリシーにより変更不可。自宅からスマホでの確認はできない（諦め済み）

## 5. 残課題・やっていないこと

| 項目 | 状態 |
|---|---|
| 画面からの更新の準備（register-autostart.bat の再実行・update.bat の実行・トークンの設定） | 依頼者の作業待ち。更新用タスクの登録（schtasks の日付書式）は実機で未確認 |
| setup-github.bat が途中で失敗したときの再発防止（中途半端な .git を検出してやり直す、update.mjs で日本語の案内） | 提案のみ・未実装 |
| バックアップ失敗のメール通知 | 未実装（画面の警告のみ） |
| 履歴CSVの月別ファイル名が日本語（`入出庫履歴_YYYY-MM.csv` 等） | そのまま。英語にするなら月の切り替わりで変える |
| PC 画面の入庫で「理由（購入・戻り・その他）」を聞かない（スマホは聞く） | 指摘のみ・未対応 |
| サーバーPCの IP 固定 | ルーターでの DHCP 予約を提案済み（依頼者側） |
| 社内 Web サービスを増やす構想（ポートを増やさずパスで振り分け） | 構想のみ |
| E2E のまれな1件の失敗（毎回違う項目） | 原因未調査。負荷が高いときのタイミングと思われる |
| サーバーPCでの実機確認 | バックアップの外付けドライブ保存、画面からの更新は Windows 実機で未確認 |

## 6. 引き継ぎ時の確認手順

1. `npm ci && npm test && npm run build && npm run e2e` がすべて通ることを確認
2. `npm run seed:demo` でデモデータを作り、`start-demo.bat`（Windows）または `ZAIKO_DEMO=1 ZAIKO_PORT=28004 ZAIKO_DATA_DIR=demo-data npm start` で画面を確認
3. `AGENTS.md` の「依頼者の方針」「用語」を守る
4. 変更したら、このファイルの「5. 残課題」と、必要なら「3. 設計判断」を更新する
